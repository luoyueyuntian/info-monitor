# 信息类型与标准化策略

更新时间：2026-06-01

## 1. 文档目的

这份文档用于回答 5 个问题：

1. 第一版为什么要按信息类型做标准化
2. 第一版支持的 4 类信息分别是什么
3. 每一类信息最少需要统一哪些字段
4. 哪些字段用于提醒，哪些字段用于沉淀和复盘
5. 哪些类型进入第一阶段主流程，哪些先作为辅助类型

这份文档定义的是产品层标准化策略，不是数据库设计，也不是抓取实现细节。

## 2. 为什么标准化要按信息类型来做

### 2.1 不按站点做第一层抽象

不同站点的页面结构差异很大，但同类信息在业务意义上往往更接近。

例如：

- 闲鱼上的二手价格
- 某股票的价格
- 黄金价格

虽然来源不同，但它们都具有：

- 时间点
- 当前价格
- 比较口径
- 历史变化

如果优先按站点做抽象，会导致：

- 每接一个来源就像新增一种体系
- 后续很难做跨渠道比较
- 产品层很难沉淀统一心智

### 2.2 按信息类型做标准化更符合当前目标

你当前最想沉淀的是：

- 多渠道抓取能力
- 标准化沉淀能力
- 历史与变化能力

因此第一版最合理的路径是：

- `主题` 作为产品入口
- `信息类型` 作为标准化入口

这样可以做到：

- 同一个主题接多个来源
- 同一类信息跨来源统一
- 同一类信息复用同一套提醒和复盘逻辑

## 3. 第一版支持的信息类型

第一版优先支持 4 类信息：

1. 价格类
2. 内容更新类
3. 新闻 / 公告类
4. 金融指标 / 事件类

其中优先级并不完全相同。

### 3.1 第一阶段主类型

和当前主场景直接对应的主类型是：

1. 价格类
2. 金融指标 / 事件类

### 3.2 第一阶段支撑类型

作为辅助和扩展的支撑类型是：

1. 内容更新类
2. 新闻 / 公告类

原因：

- 价格监控和投资信息跟踪是主场景
- 内容更新类和新闻 / 公告类能为后续扩展提供通用基础
- 它们可以先按较轻量方式进入，不必一开始就做太复杂的判断

## 4. 标准化设计原则

第一版标准化策略建议遵循以下原则。

### 4.1 先统一“最少必要字段”

第一版不要追求每类信息字段一次设计完整，而应先统一：

- 能支持历史沉淀的字段
- 能支持变化检测的字段
- 能支持提醒判断的字段
- 能支持后续人工回看的字段

### 4.2 区分“核心字段”和“扩展字段”

核心字段：

- 每类信息几乎都必须有
- 用于列表展示、过滤、比较、提醒

扩展字段：

- 只在某些来源或某些主题下有
- 用于更细分析或后续增强

### 4.3 区分“事实字段”和“判断字段”

事实字段：

- 来自来源本身
- 应尽量可追溯

判断字段：

- 来自规则或分析
- 例如重要性、利空 / 利好、是否异常

这两者必须分开，避免把推断和原始事实混在一起。

### 4.4 标准化首先服务“比较”和“回看”

第一版标准化不必一开始就服务所有高级分析，而应优先服务：

- 同类信息横向比较
- 同一主题纵向回看
- 异常识别
- 提醒触发

## 5. 通用字段骨架

虽然不同信息类型差异很大，但第一版仍建议统一一层最薄的通用字段骨架。

每条标准化记录建议至少具备以下通用信息：

- 所属主题
- 信息类型
- 来源
- 记录时间
- 原始发布时间或生效时间
- 标题或主描述
- 结构化主体内容
- 原始链接或证据入口

这些字段的作用分别是：

- `所属主题`：知道它属于哪个长期关注单元
- `信息类型`：知道该走哪套标准化和提醒逻辑
- `来源`：知道从哪里来的
- `记录时间`：知道系统何时拿到
- `原始发布时间或生效时间`：知道信息本身何时发生
- `标题或主描述`：支持列表和快速浏览
- `结构化主体内容`：支撑后续比较和分析
- `原始链接或证据入口`：支持追溯

## 6. 各信息类型的标准化策略

### 6.1 价格类

#### 6.1.1 适用范围

第一版价格类覆盖：

- 二手商品价格
- 股票价格
- 黄金价格
- 宽基指数每日收盘结果

#### 6.1.2 产品目标

价格类标准化首先要支持：

- 同主题历史价格回看
- 跨来源同类价格比较
- 最近 30 天新低识别
- 价格趋势与异常提醒

#### 6.1.3 建议的核心字段

第一版价格类建议至少统一以下核心字段：

- 标的名称
- 标的标识
- 配置或规格
- 价格值
- 价格币种
- 价格时间
- 价格类型
- 渠道名称
- 渠道内链接
- 可售状态

字段说明：

- `标的名称`：用户看到的主名称
- `标的标识`：便于同主题内聚合比较
- `配置或规格`：用于“跨平台同配置”比较
- `价格值`：当前值
- `价格币种`：避免不同口径混用
- `价格时间`：价格对应时间点
- `价格类型`：如挂牌价、成交价、收盘价、现货价
- `渠道名称`：信息来自哪个平台
- `渠道内链接`：回看与跳转依据
- `可售状态`：是否已下架、无货、停牌等

#### 6.1.4 建议的扩展字段

按不同子场景可增加：

- 卖家信息
- 商品成色
- 地区
- 价格区间
- 成交量或成交额
- 涨跌幅
- 备注标签

#### 6.1.5 提醒相关字段

价格类提醒最直接依赖的字段包括：

- 价格值
- 价格时间
- 配置或规格
- 渠道名称

第一阶段重点支持的事件判断：

- 是否创最近 30 天新低

后续可扩展：

- 是否低于目标价
- 是否出现跨平台价差异常
- 是否出现短时间大幅波动

#### 6.1.6 当前需要特别注意的标准化边界

当前已确认：

- 价格比较口径优先按“跨平台同配置”

当前仍需后续细化：

- 二手商品成色是否进入同一比较口径
- 地区差异是否单独建模
- 缺少完整配置字段时如何归类
- 股票、黄金、指数这类非商品价格，是否需要单独的价格子类型

### 6.2 内容更新类

#### 6.2.1 适用范围

第一版内容更新类覆盖：

- 产品新功能上线
- 营销活动上线
- 页面新增内容
- 说明文档或功能说明更新

#### 6.2.2 产品目标

内容更新类标准化首先要支持：

- 知道更新了什么
- 知道什么时候更新
- 知道是否属于重要变化
- 为后续竞品和产品动态场景打基础

#### 6.2.3 建议的核心字段

第一版内容更新类建议至少统一以下核心字段：

- 更新对象名称
- 更新标题
- 更新摘要
- 更新时间
- 更新类型
- 内容链接
- 内容版本标识或页面标识

字段说明：

- `更新对象名称`：哪个产品、页面或主题发生了更新
- `更新标题`：便于快速浏览
- `更新摘要`：压缩后的关键信息
- `更新时间`：内容本身的更新时间
- `更新类型`：功能更新、活动更新、文档更新等
- `内容链接`：回到原始页面
- `内容版本标识或页面标识`：用于历史比较

#### 6.2.4 建议的扩展字段

- 标签
- 功能模块
- 影响范围
- 原文 diff 片段
- 是否为首次发现

#### 6.2.5 提醒相关字段

内容更新类第一阶段不需要过重的提醒逻辑，但至少要支持：

- 是否是新增更新
- 是否属于特定更新类型
- 是否命中特定关键词

后续可扩展：

- 重要更新评分
- 同类更新频率异常

### 6.3 新闻 / 公告类

#### 6.3.1 适用范围

第一版新闻 / 公告类覆盖：

- 统计局发布公告或数据说明
- 人民银行政策公告
- 公司公告
- 媒体新闻或正式消息发布

#### 6.3.2 产品目标

新闻 / 公告类标准化首先要支持：

- 快速知道发布了什么
- 识别发布主体和发布时间
- 为后续利空 / 利好判断保留事实基础

#### 6.3.3 建议的核心字段

第一版新闻 / 公告类建议至少统一以下核心字段：

- 发布主体
- 标题
- 发布时间
- 公告或新闻类型
- 摘要
- 原文链接
- 涉及主题或标的

字段说明：

- `发布主体`：谁发的
- `标题`：核心浏览字段
- `发布时间`：何时发布
- `公告或新闻类型`：政策、数据说明、公告、新闻等
- `摘要`：压缩关键信息
- `原文链接`：追溯入口
- `涉及主题或标的`：为后续关联分析做准备

#### 6.3.4 建议的扩展字段

- 关键词
- 机构标签
- 地区
- 关联指标
- 引用来源

#### 6.3.5 提醒相关字段

新闻 / 公告类提醒第一阶段建议聚焦：

- 是否是新的正式发布
- 发布主体是否属于高优先级来源
- 是否与当前主题强相关

后续可扩展：

- 是否可能构成利空 / 利好信号
- 是否和已有事件形成联动

### 6.4 金融指标 / 事件类

#### 6.4.1 适用范围

第一版金融指标 / 事件类覆盖：

- GDP、CPI、人口等统计指标发布
- 利率变化
- 资金投放与回收
- 每日指数收盘结果
- 其他可以结构化表达的金融事件或指标值

#### 6.4.2 产品目标

金融指标 / 事件类标准化首先要支持：

- 保存时间点数据
- 保存指标值及其上下文
- 支持利空 / 利好事件判断
- 支持后续时间序列回看

#### 6.4.3 建议的核心字段

第一版金融指标 / 事件类建议至少统一以下核心字段：

- 指标或事件名称
- 发布主体
- 时间点
- 当前值
- 上期值
- 预期值
- 单位
- 事件类型
- 方向性标签
- 原始链接

字段说明：

- `指标或事件名称`：如 CPI、GDP、MLF 利率、逆回购操作
- `发布主体`：统计局、人民银行等
- `时间点`：这条数据或事件对应的日期
- `当前值`：本次值
- `上期值`：用于比较
- `预期值`：用于判断偏离
- `单位`：避免歧义
- `事件类型`：指标发布、政策发布、流动性操作等
- `方向性标签`：利空、利好、中性或未判断
- `原始链接`：追溯入口

#### 6.4.4 建议的扩展字段

- 修订值
- 影响对象
- 生效日期
- 相关政策编号
- 市场反应摘要

#### 6.4.5 提醒相关字段

金融指标 / 事件类提醒第一阶段最重要的字段包括：

- 事件类型
- 当前值
- 上期值
- 预期值
- 方向性标签
- 时间点

第一阶段重点支持的事件判断：

- 是否出现利空事件
- 是否出现利好事件

后续可扩展：

- 偏离预期幅度是否异常
- 同一时期是否出现多项同方向信号
- 是否需要提升主题优先级

#### 6.4.6 当前需要特别注意的标准化边界

当前仍需后续细化：

- 哪些事件可以直接标为利空 / 利好
- 哪些事件只适合标为中性
- 哪些事件只做事实记录，不做方向判断
- 宽基指数收盘结果归入价格类还是金融指标类，是否需要双重视图

## 7. 不同信息类型如何服务提醒、回看和分析

### 7.1 用于提醒的字段

这类字段决定某条记录是否需要打扰用户。

第一版主要包括：

- 价格值
- 价格时间
- 更新时间
- 发布时间
- 当前值 / 上期值 / 预期值
- 方向性标签

### 7.2 用于回看的字段

这类字段帮助用户之后复盘。

第一版主要包括：

- 主题
- 信息类型
- 来源
- 时间点
- 标题或主描述
- 原始链接
- 核心结构化内容

### 7.3 用于后续分析的字段

这类字段不一定立刻进入 MVP 首页，但应该尽量在标准化时考虑保留。

第一版优先考虑：

- 配置或规格
- 更新类型
- 事件类型
- 发布主体
- 方向性标签

## 8. 第一版标准化优先级建议

基于当前主场景，建议第一版按以下顺序推进。

### 8.1 优先级 P0

- 价格类
- 金融指标 / 事件类

原因：

- 直接服务当前主场景
- 事件定义已经有明确起点

### 8.2 优先级 P1

- 新闻 / 公告类

原因：

- 它是投资信息跟踪的重要事实来源
- 也能服务后续利空 / 利好判断

### 8.3 优先级 P2

- 内容更新类

原因：

- 它对后续扩展很重要
- 但不是第一阶段主场景的最核心能力

## 9. 当前明确不进入第一版标准化主流程的内容

当前不建议在第一版就重点展开：

- UGC 热度快速上升
- 复杂情绪分析
- 通用舆情分类体系
- 跨类型统一评分系统

原因：

- 这些能力和当前主场景不完全同构
- 过早纳入会拉高标准化复杂度

## 10. 当前版本的结论

当前可以明确：

- 第一版标准化优先按信息类型组织
- 价格类和金融指标 / 事件类是主标准化对象
- 内容更新类和新闻 / 公告类是支撑性类型
- 标准化的首要目标不是“完美 schema”，而是支持历史、变化、提醒和回看
