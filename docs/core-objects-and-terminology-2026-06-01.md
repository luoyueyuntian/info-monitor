# 核心对象与术语定义

更新时间：2026-06-01

## 1. 文档目的

这份文档用于统一产品讨论和后续设计中会反复出现的核心术语，避免不同文档、不同阶段对同一概念使用不同名字，导致理解偏差和后续返工。

这份文档定义的是产品概念，不是数据库表结构，也不是代码类名。

## 2. 术语设计原则

定义术语时遵循 4 个原则：

1. 优先贴近真实使用心智
2. 优先服务产品讨论和页面表达
3. 尽量让一个词只表达一个层级
4. 尽量区分“原始信息”“加工结果”“提醒结果”

## 3. 核心对象总览

当前建议使用以下核心对象：

1. 主题
2. 来源
3. 原始记录
4. 标准化记录
5. 变化
6. 事件
7. 洞察
8. 摘要

它们大致构成一条链路：

`主题 -> 来源 -> 原始记录 -> 标准化记录 -> 变化 -> 事件 -> 洞察 / 摘要`

## 4. 核心术语定义

### 4.1 主题

定义：

> 主题是一项需要被持续收集、标准化、观察和回看的信息关注单元。

主题是当前产品里最核心的对象。

示例：

- `Surface Pro 8 16G + 512G` 二手价格
- `Figma` 新功能动态
- 统计局季度 GDP / CPI 数据
- 人民银行利率与政策发布
- 沪深 300 每日收盘结果
- 某只股票价格与相关新闻

主题的特点：

- 它是长期存在的
- 它可以连接多个来源
- 它可以持续积累历史
- 它最终会沉淀出变化、事件和洞察

为什么叫“主题”：

- 比“对象”更宽，可以覆盖产品、机构、标的、指数、话题
- 比“任务”更稳定，不会让人联想到一次性执行
- 比“脚本”更贴近产品层表达

补充说明：

- 在实现或内部讨论中，可以用 `Theme` 或 `Watch` 作为辅助英文概念
- 但产品层表达优先统一用“主题”

### 4.2 来源

定义：

> 来源是某个主题的信息采集入口，即信息从哪里来。

示例：

- 某个二手平台搜索结果页
- 某个商品详情页
- 统计局公告页
- 央行政策发布页
- 指数行情接口
- 媒体新闻列表

来源的特点：

- 一个主题可以有多个来源
- 不同来源提供的信息粒度可能不同
- 来源可能失效、改版或临时不可用

来源解决的是：

- 到哪里拿信息
- 同一个主题需要盯哪些渠道

### 4.3 原始记录

定义：

> 原始记录是某次从来源获取到的原始内容或原始结果。

示例：

- 某次抓到的网页 HTML
- 某次返回的 API JSON
- 某次抓到的商品列表原始字段
- 某次新闻列表返回内容

原始记录的特点：

- 尽量接近采集结果本身
- 主要用于保留证据和排查问题
- 还不适合直接用于统一分析

原始记录解决的是：

- 当时到底抓到了什么
- 发生问题时如何回溯
- 后续标准化是否需要重跑

### 4.4 标准化记录

定义：

> 标准化记录是把原始记录整理成同一信息类型下可比较、可分析、可沉淀的统一结构。

示例：

- 价格类记录
- 内容更新类记录
- 新闻 / 公告类记录
- 金融指标 / 事件类记录

标准化记录的特点：

- 按信息类型组织
- 适合后续做历史、比较、变化和分析
- 是后续大多数产品功能的直接输入

标准化记录解决的是：

- 多渠道同类信息如何统一
- 如何支持历史存储和后续分析

### 4.5 变化

定义：

> 变化是同一主题下，标准化记录在时间维度上发生的可识别差异。

示例：

- 价格从 4200 降到 3999
- 新增了一条指标发布
- 某项利率从一个值变成另一个值
- 某产品新增了一个功能点

变化的特点：

- 它建立在历史比较之上
- 它可能重要，也可能不重要
- 它是事件判断的前置层

变化解决的是：

- 到底哪里发生了不同
- 普通更新和异常变化如何区分

### 4.6 事件

定义：

> 事件是变化中值得被用户看到、提醒或进一步处理的部分。

示例：

- 商品价格创最近 30 天新低
- 出现利空事件
- 出现利好事件
- 指数收盘达到用户关注阈值

事件的特点：

- 不是所有变化都会成为事件
- 事件通常和提醒、收件箱、优先级相关
- 事件体现的是“这条信息值得你现在看一下”

事件解决的是：

- 什么该提醒
- 什么该进入收件箱
- 什么只记录不打扰

### 4.7 洞察

定义：

> 洞察是系统基于一条或多条记录、变化、事件生成的总结、归类或初步解释。

示例：

- “该商品价格近期在多个平台同步走弱”
- “本次数据发布偏利空”
- “本周出现多次同方向变化，建议持续关注”

洞察的特点：

- 它是加工后的理解层结果
- 可以来自规则，也可以来自模型
- 它不是原始事实本身

洞察解决的是：

- 用户如何更快读懂信息
- 零散信号如何形成结论

### 4.8 摘要

定义：

> 摘要是按时间或主题对一组信息进行聚合后的简明输出。

示例：

- 今日主题摘要
- 每周价格变化摘要
- 本周重要利空 / 利好汇总

摘要的特点：

- 它是聚合视角，不是单条记录视角
- 它通常服务于低频消费，而不是即时提醒

摘要解决的是：

- 减少噪音
- 支持复盘
- 降低信息巡检成本

## 5. 这些术语之间的关系

### 5.1 主题和来源的关系

- 一个主题可以有多个来源
- 一个来源原则上服务于一个主题，但后续可以视需要复用

### 5.2 原始记录和标准化记录的关系

- 原始记录用于保留采集原貌
- 标准化记录用于统一结构和后续分析
- 标准化记录通常由原始记录加工得到

### 5.3 变化和事件的关系

- 变化是客观差异
- 事件是被判断为“值得关注”的变化

不是每个变化都要变成事件。

### 5.4 事件、洞察和摘要的关系

- 事件回答“发生了什么值得看”
- 洞察回答“这意味着什么”
- 摘要回答“这一段时间里整体发生了什么”

## 6. 当前不建议作为核心对象的概念

为了避免后续抽象混乱，以下概念当前不建议作为最高层核心对象。

### 6.1 对象

问题：

- 它看起来直观，但语义偏窄
- 对产品、商品、指数、政策、统计数据等抽象并不统一

因此当前不作为产品第一核心对象名。

### 6.2 任务

问题：

- 容易让人想到一次性执行
- 更像执行层概念，而不是产品层概念

### 6.3 规则

问题：

- 它更适合作为事件判定或提醒策略的一部分
- 不适合作为产品入口

### 6.4 信息

问题：

- 概念过宽
- 难以区分“关注单元”“原始内容”“标准化结果”

因此“信息”适合作为总称，不适合作为单一核心对象名。

## 7. 对当前主场景的映射

### 7.1 价格监控场景

- 主题：`Surface Pro 8 16G + 512G` 二手价格
- 来源：闲鱼搜索页、其他二手平台结果页
- 原始记录：各平台某次抓取的商品列表
- 标准化记录：跨平台同配置价格记录
- 变化：价格更新、新增更低报价
- 事件：最近 30 天新低
- 洞察：近期价格中枢下降
- 摘要：本周价格变化回顾

### 7.2 投资信息跟踪场景

- 主题：某只股票、黄金、沪深 300、季度 GDP、央行利率
- 来源：行情接口、公告页、统计局、央行发布页、新闻源
- 原始记录：行情数据、公告原文、发布原文
- 标准化记录：价格记录、指标记录、事件记录
- 变化：价格变化、指标发布、新事件出现
- 事件：利空 / 利好事件、阈值波动
- 洞察：短期偏利空、需持续关注
- 摘要：今日市场相关主题汇总

## 8. 当前版本的结论

当前阶段最重要的统一术语是：

- 主题
- 来源
- 原始记录
- 标准化记录
- 变化
- 事件
- 洞察
- 摘要

这些词一旦稳定，后续无论写产品目标、场景文档、MVP 还是技术方案，都会更一致。
