# MVP 范围与非目标

更新时间：2026-06-01

## 1. 文档目的

这份文档用于明确第一版产品的交付边界，回答 4 个问题：

1. MVP 要验证什么
2. MVP 必须具备哪些产品能力
3. MVP 哪些内容可以延后
4. MVP 明确不做什么

这份文档的目标不是排技术任务，而是防止第一版产品边界不断膨胀。

## 2. MVP 的核心目标

### 2.1 MVP 要验证的不是“功能多”

第一版不是要证明这个产品可以覆盖所有监控场景，而是要验证下面这条主链是否成立：

> 围绕主题持续采集多渠道信息 -> 按信息类型标准化沉淀 -> 识别少量高价值变化 -> 支持回看与提醒

### 2.2 MVP 要回答的核心问题

MVP 需要验证：

1. 主题作为产品入口是否顺手
2. 多渠道信息是否能稳定收集并标准化沉淀
3. 价格监控和投资信息跟踪这两个主场景是否真的能带来持续使用价值
4. 最近 30 天新低、利空 / 利好事件这两类高价值信号是否足够有用
5. 你是否愿意用这个系统替代一部分手动巡检

## 3. MVP 的产品定位

MVP 的定位是：

> 一个面向个人自用的信息工作台最小可用版本。

它必须优先保证：

- 主题清晰
- 数据持续
- 历史可回看
- 提醒有价值

它当前不追求：

- 场景全面
- 配置高度灵活
- 分析能力很强
- 对外可售卖

## 4. MVP 服务的主场景

MVP 只围绕以下两类主场景组织。

### 4.1 主场景 A：价格监控

MVP 必须支持：

- 为某个价格主题配置多个来源
- 保存历史价格记录
- 支持跨平台同配置比较
- 识别最近 30 天新低
- 对重要价格变化提醒

### 4.2 主场景 B：投资信息跟踪

MVP 必须支持：

- 为某个投资主题配置多个来源
- 保存价格类、新闻 / 公告类、金融指标 / 事件类记录
- 识别利空 / 利好事件
- 对重要金融事件提醒
- 支持按主题回看历史

## 5. MVP 必须具备的核心能力

### 5.1 主题管理

MVP 必须支持：

- 创建主题
- 编辑主题
- 暂停主题
- 恢复主题
- 查看主题列表

为什么必须有：

- 主题是整个产品的入口
- 没有主题管理，产品会退化成分散任务和分散来源

### 5.2 来源管理

MVP 必须支持：

- 为一个主题添加多个来源
- 查看来源状态
- 手动触发来源刷新
- 暂停某个来源

为什么必须有：

- 多渠道是当前产品价值的核心之一
- 来源经常出问题，必须可见可控

### 5.3 标准化记录沉淀

MVP 必须支持：

- 价格类记录标准化
- 金融指标 / 事件类记录标准化
- 新闻 / 公告类记录基础标准化
- 基础历史记录保存

为什么必须有：

- 这是后续提醒、回看和分析的前提
- 也是第一阶段最重要的能力沉淀

### 5.4 历史回看

MVP 必须支持：

- 查看某个主题的历史记录
- 按时间查看变化
- 回看关键事件

为什么必须有：

- 如果不能回看，平台就只是一个提醒器
- 你想要的是长期信息资产，而不是一次性消息流

### 5.5 事件识别

MVP 必须支持至少两类高价值事件：

1. 最近 30 天新低
2. 利空 / 利好事件

为什么必须有：

- 这是当前已确认的最重要提醒逻辑
- 没有事件识别，MVP 很难体现筛选价值

### 5.6 提醒与摘要

MVP 必须支持：

- 即时提醒
- 按主题查看重要事件
- 基础摘要视图

为什么必须有：

- 只存数据不提醒，很难形成使用习惯
- 只提醒不聚合，也不适合长期使用

### 5.7 运行状态可见

MVP 必须支持：

- 看见哪些主题正常运行
- 看见哪些来源最近失败
- 看见最近一次成功更新时间

为什么必须有：

- 这是一个长期运行系统，不是单次工具
- 没有可见性就无法稳定维护

## 6. MVP 推荐具备但可适度简化的能力

这些能力很有价值，但第一版可以做轻一点。

### 6.1 新闻 / 公告类基础摘要

建议有，但可以先做成较轻量输出：

- 标题
- 时间
- 来源
- 简短摘要

### 6.2 内容更新类基础接入

建议预留，但不要求一开始深做。

最低可以做到：

- 能记录有无更新
- 能保存更新时间和链接

### 6.3 基础筛选

建议支持：

- 按主题筛选
- 按信息类型筛选
- 按事件类型筛选

但不必一开始就做复杂查询系统。

## 7. MVP 的核心页面边界

MVP 建议至少有以下 6 个页面或等价视图。

### 7.1 首页 / 收件箱

作用：

- 展示最近值得关注的事件
- 作为你每天打开后的第一入口

### 7.2 主题列表

作用：

- 查看所有主题
- 快速了解运行状态和最近变化

### 7.3 新建 / 编辑主题页

作用：

- 创建新主题
- 编辑主题基础信息
- 管理主题来源和提醒方式

### 7.4 主题详情页

作用：

- 查看该主题的来源
- 查看该主题的历史记录
- 查看该主题的关键事件

### 7.5 事件详情页

作用：

- 查看事件来源
- 查看变化依据
- 查看摘要和方向性判断

### 7.6 来源状态页

作用：

- 查看来源健康情况
- 发现失败和中断

## 8. MVP 明确不做什么

为了保证第一版收敛，以下内容明确不进入 MVP。

### 8.1 不做完整的决策助手

MVP 不追求：

- 自动给出复杂建议
- 自动生成完整投资判断
- 自动执行动作

### 8.2 不做多用户与协作

MVP 不包括：

- 团队空间
- 共享主题
- 权限体系
- 协作分工

### 8.3 不做完整无代码配置

MVP 不要求：

- 所有来源都通过 UI 配置
- 所有规则都可视化配置

允许通过代码或半手工方式接入来源。

### 8.4 不做复杂通用规则系统

MVP 不做：

- 通用 DSL
- 可视化工作流编排
- 高度抽象的规则引擎

当前只需要支撑已确认的少量高价值事件。

### 8.5 不做复杂趋势 / 热度分析

MVP 不包括：

- UGC 热度异常检测
- 情绪趋势图谱
- 舆情平台式能力

### 8.6 不做复杂评分体系

MVP 不要求：

- 所有事件统一评分
- 所有主题统一健康分或机会分

### 8.7 不做完整移动端产品

MVP 可以优先以桌面网页或桌面优先体验为主。

## 9. MVP 的成功标准

MVP 是否成立，不看功能数量，而看以下结果。

### 9.1 使用结果

- 你愿意持续维护几个真实主题
- 你愿意每天或每周打开系统查看
- 你减少了手动巡检频率

### 9.2 信息质量结果

- 价格历史能稳定积累
- 金融事件能被持续记录
- 最近 30 天新低和利空 / 利好提醒有实际价值

### 9.3 产品体验结果

- 主题心智清楚
- 来源状态可见
- 事件和历史回看都可用

## 10. MVP 之后最自然的增强方向

MVP 成立后，再考虑下一步增强：

- 更丰富的价格异常判断
- 更细的利空 / 利好分类
- 更强的新闻 / 公告摘要
- 内容更新类的深度支持
- 趋势 / 热度场景纳入

## 11. 当前版本的结论

当前可以明确：

- MVP 只围绕价格监控和投资信息跟踪组织
- MVP 的核心价值是主题、多渠道、标准化、历史、事件提醒
- MVP 不做平台化过重能力
- MVP 的目标是验证“持续采集和沉淀 + 少量高价值提醒”这条主链
